\section{Task Overview}
% Item 2: Task title and overview, significance, what makes it challenging
We are creating a program to catalogue various orchestral instruments based on their waveform. 
Many musicians find it very difficult to catalogue instruments because many instruments do not have physical identifiers on them.


This task is challenging because the raw waveform must be converted with a Fourier transform into time--frequency features such as a spectrogram.

% ============================================================
\section{Task Definition}
% Item 3: type of data, classification/regression/generation, number of classes, single/multi-label
The data we are working with is an audio .mp3 file. This is a single-label, multi-class classification task with 19 classes, one per instrument in the dataset: flute, oboe, cor anglais (English horn), clarinet, bass clarinet, bassoon, contrabassoon, saxophone, French horn, trombone, trumpet, tuba, banjo, cello, double bass, guitar, mandolin, viola, violin. Each clip is one note by one instrument. We have multiple features: fundamental frequencies, timbre, resonance, harmonics, noisiness/dynamics.

% ============================================================
\section{Problem Description and Impact}
% Item 4: Describe the problem, its impact on the real world, and why it is challenging

Suppose a recording of a composition uses a certain wind/string instrument, and we want to find the same instrument again. Being able to say what instrument a sound came from based on how it sounds makes it easier to search.

The challenges are: (1) audio analysis requires knowledge of signal processing; we will be using Fourier transforms; (2) the same instrument sounds different across pitches, dynamics and articulation, so the model must not just learn ``pitch'' or ``loudness'' as a shortcut; (3) many instruments in the same family share very similar timbre; (4) because the recordings are really clean, this may not transfer to real-world recordings.

\section{Proposed Solution}
% Item 7: modeling approach, features/labels, candidate models, existing solutions,
% 2-5 cited sources, evaluation plan, libraries

Our pipeline will be as follows: decode the .mp3, convert to mono, resample to 16kHz, trim silences, and normalize clip length by padding or cropping to a fixed length (1-2 seconds, will be determined experimentally). 

We can then use the cleaned data to process inputs for a model. We have two options, building hand crafted features like MFCC mean and standard deviation, spectral centroid, rolloff, flatness, zero-crossing rate, and attack time for a classical SVM or random forest model, or log-mel spectogram for a small CNN with about 4 conv blocks. 

We will also evalutate the dataset further:
\begin{itemize}[noitemsep]
    \item A grouped split, where we group all clips by `(instrument, pitch)', so the same note at different dynamics or durations never appears in both train and test. Without this the accuracy of the model would be artificually inflated by memorizing the pitch of the note.
    \item We use macro F1 score and balanced accuracy as our metrics, since the dataset is imbalanced across instruments. (There are 1,502 violin clips, and while some of the other instruments dont even have clip counts above 100.)
    \item Tuba, contrabassoon and double bass can be identified by pitch alone. Therefore, we will evaluate on the pitch range where instruments overlap, or hold out whole pitches.
\end{itemize}
